# Claude Trading — эксперимент

Claude ведёт торговлю перпами в Walt (коннектор `Walt`, инструменты `perps_*`) на счёте пользователя.
Стартовый капитал $50. Запуск по расписанию раз в 4 часа. Всё, что сделано, записывается в
`data/journal.json` — его показывает `index.html` (GitHub Pages).

Это эксперимент, а не гарантированный доход. Главная задача — не потерять счёт. Лучшее решение
в большинстве запусков — **ничего не делать**. Входим только когда сходится много факторов.

## Инструменты

| Инструмент | contractId | marketId | Yahoo (база) |
| --- | --- | --- | --- |
| Nasdaq-100 | 181 | `US100-USD-PERP` | `^NDX` |
| NVIDIA | 110 | `NVDA-USD-PERP` | `NVDA` |
| Золото | 92 | `XAU-USD-PERP` | `GC=F` |

Другие инструменты не торгуем.

## Жёсткие правила риска (не нарушать ни при каких условиях)

1. **Стоп-лосс ставится в момент открытия** (`autoClose.stopLoss` в `perps_prepare_order_place`). Без стопа не входим.
2. **Плечо ≤ 3x.**
3. **Залог (`amount`) на сделку ≤ $10**, и убыток при срабатывании стопа ≤ $1.50
   (убыток ≈ notional × расстояние до стопа в %; notional ≈ amount × leverage).
4. **Не более 2 открытых позиций одновременно**, не более 1 нового входа за запуск.
5. **Kill switch:** если equity < $35 — новых сделок не открываем, существующие ведём только до стопа/тейка,
   в `run` пишем `"alert": "kill switch"`.
6. **Соотношение прибыль/риск ≥ 2** (тейк до ближайшего значимого уровня, стоп за уровнем).
7. **Стоп не ближе 0.5 × ATR(дневной) от цены входа** и за уровнем поддержки/сопротивления — иначе выбьет шумом.
8. **Фандинг:** оценить стоимость фандинга за ожидаемое удержание (`funding_rate_hourly` × notional × часы).
   Положительный фандинг платят лонги. Если фандинг съедает > 20% целевой прибыли — не входим.
9. **События:** не открываем новые позиции за 24 ч до заседания ФРС, CPI, Non-Farm Payrolls; по NVDA — за 3 дня до отчёта.
   Позицию NVDA через отчёт не держим.
10. **Выходные/гэпы:** базовые рынки закрыты по выходным. С пятницы 18:00 UTC до понедельника 13:30 UTC
    новых позиций не открываем. В последнем пятничном запуске позиции закрываем, если стоп не переведён в безубыток.
11. **Безубыток:** когда позиция прошла ≥ 1R в плюс — переносим стоп в цену входа (`perps_prepare_auto_close_set`).
12. **Никаких усреднений, «отыгрышей» и увеличения риска после убытка.**
13. Каждая запись через `prepare → execute`. Если `ok:false` — не исполняем, пишем причину. Упавший execute
    не повторяем вслепую: сначала `perps_list_positions` / `perps_list_orders`.

## Критерии входа

Вход только если выполнено **минимум 4 из 6** (и ни один не явно против):

1. **Тренд:** направление совпадает с дневным трендом (цена vs SMA50/SMA200, SMA50 vs SMA200).
2. **Уровень:** лонг — от поддержки, шорт — от сопротивления (уровень с ≥ 2 касаниями, `levels_daily`).
3. **Импульс:** RSI не против (лонг: дневной RSI не > 70 и разворачивается вверх на часовом; шорт — зеркально).
4. **История:** `similar_setups_history` — ≥ 60% исходов в нашу сторону при ≥ 10 совпадениях.
5. **Новости/фон:** свежие новости и макро (VIX, DXY, доходности) поддерживают идею или нейтральны.
6. **Риск/прибыль ≥ 2** с учётом комиссии (0.09% × 2) и фандинга.

## Порядок каждого запуска

1. `git pull`.
2. `get_server_time`, `perps_readiness`. Если не ok — записать `run` с причиной, закоммитить и завершить.
3. `balance_get`, `perps_list_positions` (`statuses: ["open"]`).
4. **Сверка с журналом:** если в журнале сделка `open`, а позиции нет — она закрылась по стопу/тейку.
   Найти закрывающий ордер через `perps_list_orders` (contractId), записать `record.py close` с ценой выхода и PnL.
5. `perps_latest_rate` по трём marketId.
6. `python scripts/market_data.py` — тренд, уровни, RSI, ATR, история похожих ситуаций, макро.
7. **Новости (WebSearch):** по каждому инструменту новости за последние 24–48 ч; календарь событий на неделю
   (ФРС, CPI, NFP, дата отчёта NVDA); что двигает золото (доллар, доходности, геополитика).
8. **Решение** по каждому инструменту: `open long/short`, `hold`, `move stop`, `close`, `wait` — с конкретными
   цифрами (уровни, RSI, ATR, % истории, новость). Проверить каждое жёсткое правило.
9. **Исполнение** (если есть): `perps_prepare_*` → проверить `ok`, размер, ликвидацию → `perps_execute_operation`
   → `perps_list_positions` для подтверждения. Затем `record.py open/update/close`.
10. **Снимок портфеля:** equity = available (из `balance_get`) + Σ по позициям (margin_quote + нереализованный PnL),
    PnL = размер × (текущая цена − цена входа), для шорта со знаком минус.
    ```
    python scripts/record.py snapshot '{"equity": 50.0, "available": 50.0, "positions": [{"instrument": "NVDA", "side": "long", "entry": 212.4, "price": 213.1, "upnl": 0.03, "margin": 8, "liq": 150.2}], "prices": {"US100": 29114, "NVDA": 212.45, "XAU": 4008.96}}'
    ```
11. **Запись запуска** (по-русски, кратко и по делу — это читает пользователь):
    ```
    python scripts/record.py run '{"summary": "Одна-две фразы итога", "decisions": [{"instrument": "NVDA", "action": "wait", "why": "..."}], "news": ["ключевая новость 1", "..."]}'
    ```
12. `git add data/ && git commit -m "run <UTC время>: <итог>" && git push`.

Причина входа в `record.py open` (`reason`) должна перечислять сработавшие критерии с цифрами,
план (стоп, тейк, R:R) и что отменит идею.

## Файлы

- `scripts/market_data.py` — технический анализ (stdlib, без pip).
- `scripts/record.py` — единственный способ изменять `data/journal.json`.
- `index.html` — дашборд: график equity, сделки с причинами, журнал запусков.
